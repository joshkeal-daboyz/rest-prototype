## What the ticket asked for, as I understood it
A chapter 16 of `docs/city-style-guide.md` that works as a grammar for building a City Pack city (lot to roof prop, variety, dressing, furniture, exclusions, fallbacks) and holds an evaluation protocol (three maps, 28 views, checklist R1 to R12). Also a pure `citymetrics.ts` whose automatic items run on every `npm test` against `CITY_CHECK`, each one shown failing on a plan built to break it, plus drift checks that tie the guide's Numbers table and "Never used" table to the code.

## Does the branch do it?
Reviewed at 9926319 against `goal/city-style`. The gate was reported green (1967 tests). As asked, I did not re-run the suite.

- **AC1 (Numbers rows plus a new drift check).** Met. `styleguide.test.ts` adds "every numeric export of the city files has a Numbers row". It walks the exports of `stacks.ts`, `terrace.ts`, `dressing.ts`, `furniture.ts`, `streetcam.ts`, `citymetrics.ts` and the `TERRACE_`/`PARKING_`/`PLAZA_` exports of `town.ts`. It counts a number, an array (as `[i]` rows) or a record (as one row or `.k` rows), and fails on any name with no row. A floor (`checked > 80`) stops the check from passing with nothing found. `CITY_CHECK` is one record row, `0.9 x 1 x ... x 0`. The 051 B town rows are named explicitly. ## Rule conflicts and risks
- No Decided rule is touched. No `src/grid/` or `src/night/` change, no new dependency, no `src/core/` change. `citymetrics.ts` imports only types and constants from pure render3d modules, none of which import `three`.
- **Flag 2, the three lowered thresholds.** They are honest and documented, and no rule was changed to pass. The builder did not edit the 051 or 052 code it is not allowed to touch. Each shortfall is recorded as an Open "waits for a re-cut of 051 C / 052 A" line in 16.9, and the per-run R1 number is still measured (`runsUnderFrontage`, `minFrontageCovered`). The alternative was a red gate, or editing `dressing.ts` or `terrace.ts`, which the ticket forbids ("a rule the chapter finds wrong is reported for a re-cut"). So none of the three is a must-fix for this branch. Each is a deviation from a default the ticket set, and Josh must see it as a decision, not as a pass:
  - R1: "0.9 per run" became 0.9 of the map's frontage, measured 0.968. 3 to 8 short runs per map fall under 0.9, the worst at 0.67. This is a semantic change, not just a number. A map-wide 0.9 is loose against 0.968 and would let several more bad runs in unnoticed.
  - R5: 0.6 became 0.55; `09-shrine-circuit` measures 0.584.
  - R8: "every roof dressed" (1.0) became 0.9, measured 0.94 to 0.96. "A big roof prop per run" became 0.5 of runs, measured 0.55 to 0.59.
- **Flag 3, R7 and R6.** R7 meets the ticket's own default of 0.5. "Most" in the reference is the ticket's own gap, and 16.9 records it as Open. R6 on `01-first-light` is 0.505 against 0.5, as is R5 at 0.584 against 0.55. Margins this thin mean an unrelated change to the hashing or layout can turn these items red. That is a real check, but whoever reads the failure should know the margin was 1%.
- **Wording in 16.8's "What the reference shows" column.** The R1 and R8 rows were reworded to fit what the code does: "most of the frontage covered" and "a big roof prop on many rows", where the ticket said "at least one big roof prop per run". That column should describe the reference, and the shortfall belongs in 16.9 (where it already is).
- **Flag 4, "one open lot per run" read per kind.** This is consistent with 051's own recording rule: a plaza belongs to the run after it, a parking lot to the run it ends. 16.2 and the R1 row state it. Fine.
- **Flag 8, 10-digit decimals** (`KERB_FROM_FRONT_M`, `WALL_EDGE_M`, `KERB_M` = 3.3333333333 / 0.8333333333). These are within the drift test's 1e-9 tolerance, so they hold. They are derived values (10/3 m and similar), written as decimals.
- **Out-of-scope file.** The builder edited `docs/overnight-city-goal-notes.md`, which is not in the ticket's Files list. It added the 052 B, 052 C and 053 rows and rewrote item 6, which belongs to 051 D. The content looks accurate and harmless, but that file is the main session's record for Josh. It also says nothing about the three lowered thresholds, the one thing from this ticket Josh must decide.
