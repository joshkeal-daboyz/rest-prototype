## Rule conflicts and risks
- No hard-rule break found. No changes in `src/grid/`, `src/night/`, `src/core/` or `src/city/pipeline/`, no new dependency, no locked puzzle touched. `fixtures.ts` imports `pipeline/eras` and `pipeline/readable`; it is test-only support and the import already existed in kind.
- **`size` no longer means the key's bounds for ruin trees.** `src/core/cityera.ts` documents `CityEraPiece.size` as "the key's bounds, as `CityGroundProp.size`". A ruin sapling or park tree now carries its trunk square (for example 2.2 x 2.2 x 1.7 m for the giant, whose crown is 12.6 x 13.1 x 11.2 m). The branch needed this because `readable.ts` reads `size` before `options.bounds`. It is inside the ticket's folder and gives what the ticket asks (T-2 and the index see the trunk). But anything downstream that sizes, culls or picks a ruin tree by `size` will get the trunk, notably F3's drawing and any plan audit. The core doc comment is now wrong for these pieces. This is for the architect to record (F3 must read `ruinCrownBounds` or the key's bounds), not for this branch, which may not edit `src/core/`.
- **All ruin trees now stand at yaw 0.** `trySapling` and `tryParkTree` no longer draw a yaw, and `treeAt` writes `yaw_deg: 0`. The ticket did not ask for this, and every copy of a key will face the same way once drawn. The trunk disc does not depend on yaw, and `crownSized` already handles turns.
- **Low trunk tops.** Tree_Birch_02's measured `top_m` is 0.22 m, so its trunk is checked only against pieces that start below 0.22 m. That follows the ticket's definition (trunk top = crown base) and Josh's "outside of where they start their growth". But a raised piece over a pavement whose base sits between 0.22 m and the real trunk's height would not keep that tree's trunk out.
- **The trunk is judged as a square, not a disc.** `trunkVerdict` uses distance from the square of side 2r. That is slightly stricter than a disc at the corners, and it matches what T-2 and the obstacle index read, so it errs safe.
- **One small refusal the ticket did not name.** Tree-vines gained a `meetsBuilt` check in `grow.ts` (`tryTreeVine`). It is a reasonable result of crowns now reaching over buildings, but it is a new refusal on a step the ticket said stays "as merged".
