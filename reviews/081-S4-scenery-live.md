## What the ticket asked for, as I understood it
On `city-two-ways-round`, each scenery building S1 hung on the job's live poles lights its windows through L1's path (with L2's street light and L3's exclusion), and its drop joins the live layer as a wire of its own, lit from its hidden lamp. Hidden nodes never show as icons or pick proxies. 3 test cases, in `cityview.ts`, `windows.ts` and `windows.test.ts`.

## Does the branch do it?
The diff against `origin/main` (17df2e5) touches `src/render3d/cityview.ts`, `windows.ts` and `windows.test.ts` and nothing else. It adds 3 `it(` cases. I ran `npx vitest run --maxWorkers=2 src/render3d/windows.test.ts`: 11 passed, 4.3 s for the file (the slow case is L1's existing one; the three new ones are quick on the shared city).

1. **The windows.** Met. `sceneryLamps(converted, buildings)` in `windows.ts` is pure. It groups each scenery building with its lead and the lead's followers, the same way `lampBuildings` reads L1. `cityview.ts` merges its entries into `lampsOf` after the job lamps' buildings, so L1's levels, the shop glass, L2's lights (in `lampsOf` order) and L3's exclusion all pick them up with no change of their own. The test "a scenery building maps to its hidden lamp, dark while that lamp is dark and lit once current reaches it" checks the mapping for every `scenery` entry on P0. It runs `buildingGlow` against real grid states, before and after `sw` + `repair l_e2`: 0 when the lamp is dark, above 0 when it is lit, and some buildings dark at the start. I probed P0 on seed 1: 22 scenery buildings give 44 `lampsOf` entries with their partners. None of them is one of the 6 job-lamp buildings, and no building carries two hidden lamps.
2. **The live drops.** Met, with a timing note under Could improve. `sceneryDropWires` builds one `JobWire` per `layer.drops` entry whose building is in `converted.scenery`, on the hidden line `<attach>~s~l`. `circuitdraw.ts` hangs the drop from the pole's insulator to the seat, so `flip: false` lights it from the pole end. `liveWires` (job wires plus drops) sizes the existing instanced glow and pulse meshes at build, so no mesh is added. The brownout wobble is the same `lampFlicker` call the spans use. Picking and the cuts still read `wires` only. The test "the live layer holds one drop wire per scenery building..." checks that the ids equal `drop:<b>` for exactly the `scenery` keys, that `layer.drops` is larger (so other drops are left out), that each wire's line runs to its building's hidden lamp, and that no `runs` entry exists for it.
3. **Hidden nodes stay hidden.** Met. On P0, `overlayIcons` gives no hidden id, and `jobWires`, which the wire proxies are built from, names no hidden line. The node proxies are built only where `draws.pieces`/`removed` has the node's id, and hidden nodes have no place. The test does not assert that part directly (Could improve 3). `overlay.ts` is not edited.
4. **The budget.** Can't tell from here: it is a browser measure. Structurally no draw call is added (the glow and pulse instancers are only sized larger at build, and the street lights are fixed at build with `STREET_LIGHTS_MAX` = 32), so no program should compile in play. The main session should confirm the builder's `perf=1` numbers before Josh plays.
5. **Josh plays it.** Browser, his.

## Rule conflicts and risks
- No change to `src/grid/` or `src/night/`, no new dependency, no file outside the ticket's list. The tests import `src/city/` and `src/grid/`, which tests are allowed to do.
- Lamps stay leaves, and a building past the cut stays dark: drops and windows read only `state.lit` / `state.powered` of the hidden lamp and line. "Live drops glow" goes against the GDD's Draft "Live cables don't glow". The ticket records that Josh's card stands for the prototype.
- **Extra scope:** `linesAround` / `wholeFraction` change how every split file line's run is paced in the Relight. The run is now lit from the start of `L~a` to the end of `L~b`, where before it used `L`'s middle third. This is a real consequence of S1's split, and the code sits in `cityview.ts`'s live layer, a file the ticket lists. But no criterion asks for it, and it also changes FX2's `fxReached`. The second test carries it.
- `wholeFraction` falls back to `lineFraction(L)` when `L~a`'s start or `L~b`'s end is not finite. That happens, for example, in a Relight where a cut on `L` is still live and `L~b` is never reached. The glow would then start at `L~h1`'s arrival rather than at the run's start. This may occur, not checked.

## Could improve
1. **Drop timing against the span glow.** I probed P0 seed 1 at the win, using the Relight plan. Every `l_n~h1` building's drop lights over 0.77 to 1.28 s, as one batch. On the same run the span glow reaches those buildings' poles anywhere from 0.48 s (`pole:z:6:hi:237.50`) to 1.33 s (`pole:z:7:lo:264.33`). So some drops glow, and their windows ignite, before the current visibly reaches their pole, and others wait after it. I worked out the pole fractions from the spans' `a0`/`a1`, so read these numbers as approximate. Most of the cause is S1's design: one hidden lamp per attachment point, at `L~h1`/`L~h2`. The criterion's "lit from the pole end at the lamp's arrival" is read here as *finishing* at the lamp's arrival. If Josh notices it on play (criterion 5), the render-side fix would be to start each drop when the span glow reaches its own pole.
2. Record the `wholeFraction` pacing change in the ticket (architect's), since it changes every job span's Relight and FX2's reach, not just the scenery.
3. Criterion 3's test could also assert that `draws.pieces` and `draws.removed` hold no hidden id, which would cover the node proxies directly.
4. `sceneryLamps` would add a hidden lamp to a job-lamp building if that building were the partner of a scenery building. The job building would then light from scenery current while its own lamp is dark. This does not occur on P0 seed 1 (checked: no overlap). On other cities it may occur, not checked. S1 excludes only the lamp's own building, not its partners.
